## 3. 架构对比

### 3.1 c4 vs FSG

| 特性 | c4 (C) | FSG (汇编) |
|------|--------|------------|
| 源码行数 | ~400行 | ~200行 (v0) |
| 目标代码 | x86字节码 | FSGB字节码 |
| 语言特性 | C子集 | 汇编 |
| 自举方式 | C编译器编译C | Python编译FSG汇编 |
| 指令数 | 35条 | 34条 |

### 3.2 指令集对照

| 类别 | c4指令 | FSG对应指令 |
|------|--------|-------------|
| 加载 | LEA, IMM, LI, LC | LOADIMM, LOAD |
| 存储 | SI, SC | STORE |
| 算术 | ADD, SUB, MUL, DIV, MOD | ADD, SUB, MUL, DIV, MOD |
| 比较 | EQ, NE, LT, GT, LE, GE | CMP + 条件跳转 |
| 跳转 | JMP, BZ, BNZ | JMP, JE, JNE... |
| 函数 | JSR, ENT, LEV | CALL, RET |
| I/O | PRTF | PRINT, PRINTS |

## 6. 技术洞察

### 6.1 自举关键因素

1. **极简主义**: c4证明了400行代码足以实现自举编译器
2. **虚拟机设计**: 简单但完备的虚拟机是关键
3. **增量开发**: 从最小可行编译器开始，逐步增强
4. **测试驱动**: 每个功能立即验证

### 6.2 FSG优势

1. **类汇编语法**: 更接近硬件，容易手工编写
2. **固定指令长度**: 简化编译器开发
3. **段机制**: 代码/数据分离，清晰
4. **标签支持**: 完整的跳转控制流

### 6.3 面临的挑战

1. **汇编器限制**: 当前assembler.fsg功能简单
2. **调试困难**: 缺少源码级调试
3. **性能优化**: 手写汇编效率可能较低
4. **代码量**: 完成完整编译器需要数千行代码
